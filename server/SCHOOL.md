# Connected school workspace

Sign in normally, then choose **Teach**. Every account can create and manage its own classes; this does not grant access to an institution or another teacher's classes. Students use **Home → Join class** and the code provided by their teacher.

The dedicated assignment page supports a title, instructions, a class, extra students from the owner's other classes, optional deadline, estimated minutes, study-task-list inclusion, resource links and optional grading. Scales include 1–10, RAG, F–A+, E–A*, pass/fail and comma-separated custom choices. Drafts can be edited; published assignments cannot currently be edited. Grades are shared with the individual student when saved.

Classes, memberships, assignments, extra recipients, completion timestamps, grades and feedback are stored in PostgreSQL (migration 004). All school API calls require Firebase ID tokens. Class ownership and assignment recipient checks are enforced on the server. Each mutation runs in a transaction. Student completion updates cannot overwrite grades. The UI refreshes school data every 15 seconds.

Run `node scripts/check-school.mjs` for transaction-scoped integration checks; its temporary records are rolled back. `npm test` checks HTTP readiness and authentication behavior. `npm run check` verifies database restrictions and readiness.

Migration 005 adds assignment/discussion attachments and class discussions. Files are stored as PostgreSQL bytes, with 10 files per assignment/post, 10 MB per file and 25 MB combined. Saving files and their parent record is atomic. Downloads use verified Firebase identity and current class/assignment access, and are always served as downloads rather than executable inline content. Deleted discussion attachments are unavailable to students. Database backups must include the file tables.

Teachers can rename classes, enable discussions, independently allow student posts/replies, lock threads, and remove/restore posts. The composer sits below messages, with an arrow on the left; Enter sends on pointer-based computers and Shift+Enter inserts a line break. Discussions refresh every 10 seconds. Run `node scripts/check-sharing.mjs` to check file/privacy/moderation access and HTTP transaction rollback; fixtures are rolled back.

This is still a local backend. Internet hosting, backup automation and school administrator verification remain to be set up. Existing demo classes/attachments/discussions remain separate in browser storage; they are not silently imported. Resource URLs should use links that students have permission to open. The sample class and unpublished sample assignment created during UI verification are clearly named and contain no student records. For a larger deployment, move file bytes into object storage and add storage quotas and malware scanning before accepting untrusted uploads at scale.

Migration 006 stores emoji reactions separately from discussion replies. Every member can add/remove their own reactions to available messages, even in reply-only or read-only posting mode. Turning off discussions blocks student reactions. Deleted posts and replies cannot receive reactions. The picker has searchable emoji names and aliases; count buttons show member display names, without exposing emails or Firebase IDs. Repeated requests are idempotent. The local demo uses matching controls backed by its existing browser store.

## Submissions and notifications

Migration 007 adds private student drafts, text/file submissions, version history, teacher review, requests for changes and resubmission. Students open School tasks → Start assignment/Open your work. Saving a draft stores it on the backend but does not expose its answer or files to the teacher. Submit work freezes that attempt; returning it or requesting changes enables a new revision. Old attempts, attachments and feedback remain accessible to that student and the class owner. Draft file access is student-only. Up to 10 files, 10 MB each/25 MB total, and 20,000 answer characters are accepted.

Teachers use Progress & grades to view submissions and return a grade/feedback or request changes. Ungraded assignments support written feedback too. Graded work needs a grade to be returned; requesting changes needs written feedback. Version checks prevent stale drafts and reviews overwriting newer work. Existing completion markers and legacy grades remain stored; marking work done is not treated as a submission.

In-app notifications cover available published assignments, new submissions, returned work and change requests. Deadline reminders are created once per due date for work due today or tomorrow (Europe/Warsaw), when school data is refreshed. These are in-app reminders, not email/push or an offline scheduler. Read state is saved per account. Opening an assignment notification opens the corresponding student work or teacher review.

Run `node scripts/check-submissions.mjs` for an end-to-end database integration check, including file/privacy isolation, revision history, stale writes, ungraded feedback and notification deduplication. Fixtures are rolled back. This workflow is for real signed-in accounts using the connected school workspace; the separate local Sample Academy demo retains its earlier completion workflow.

## Gradebook

Teach → Open gradebook opens a separate page with full-name rows, assignment columns, class filters and name search. Each editable cell uses the assignment grading scale. Saving shares the grade with the student; for submitted work it also returns that attempt. Concurrent grade edits are checked by revision. Draft, ungraded and unassigned cells cannot be graded.

Migration 008 stores a private school full name separately from the public Community username. Existing students can add it on Home → Your name for school. Missing names are labelled explicitly, without substituting usernames. Only teachers owning the relevant classes can access their gradebook. Run `node scripts/check-gradebook.mjs` for roster, privacy, grading and stale-write checks.

## Personal tasks

The student dashboard has a top School / Study mode bar. Study mode → Tasks opens the personal list; Create new task opens a native modal dialog with a name, optional due date, editable date set defaulting to the local current date, description and attachments. Signed-in task creation, editing, completion and deletion use authenticated /api/tasks endpoints. Personal tasks and attachments are private to their owner, including against teachers. Migration 009 adds versioned personal tasks and task attachment ownership. Files use the existing 10-file / 10 MB per file / 25 MB combined limits and transaction rollback. Deleting a task deletes its files. Browser-only tasks remain available for explicit copying into the account; demo tasks stay local. Test with node scripts/check-tasks.mjs (fixtures roll back).

Student navigation now uses an icon sidebar with Home, School, Study, Classes and To-do list. Its menu button reveals labels; narrow screens overlay the expanded rail. Student sessions start on the dashboard on each fresh tab, while the locally remembered teacher workspace remains available for teacher sessions. Home summarises pending school and personal tasks alongside deadlines and classes. Sidebar customisation is deferred.

Both workspaces now share the compact animated navigation rail. Student navigation includes Settings; real teacher navigation uses Home, Classes, Assignments, Gradebook and Settings. Home summarises work, Classes manages membership codes and class settings, and Assignments manages drafts/publication/review. The local teacher demo uses Progress and Calendar in place of the connected Gradebook. Its former teacher navigation is removed. Settings includes appearance/accessibility alongside account settings. Class tabs remain contextual navigation within a class.

## Commendations and demerits

Migration 010 stores behaviour points in PostgreSQL. Behaviour in either sidebar opens an account-specific overview. Students see only their own points, a type-ratio pie, a commendation-by-subject pie and the latest four points. Teachers see only points they awarded, the ratio pie, recent awards and their A–Z class list. Hover/focus/tap chart slices for counts and percentages; chart legends expose the same numbers. See more opens a sortable history table. Date first sorts newest, then oldest; all six headers are sortable. Teacher/subject filters (student/subject for teachers) support multiple selections; Deselect all restores the full list. Select a row/title to expand its description, category, class and intervention notes. Overviews refresh every 15 seconds while open.

Teacher Behaviour → a class opens that class’s Behaviour tab. Selecting a student opens a portrait popup with Commendation and Demerit choices. Both require title, date, subject and description; demerits additionally require one of the six categories and record whether an intervention occurred, with optional details. Commendations have no category or intervention. Saves verify class ownership and current membership. A unique request id makes identical retries return the original record, preventing duplicate points. Students cannot award themselves or view classmates’ records; other teachers cannot view or award into unowned classes. These routes use verified Firebase identity and transactions. The local bypass demo requires a real sign-in to access behaviour records; it does not write real student data. Run node scripts/check-behaviour.mjs for authenticated HTTP, privacy, validation and retry checks; temporary records roll back.
